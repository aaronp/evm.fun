# Cross-chain swap (hash-locked): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Roadmap step 3 — GBP on one chain swapped for USD on another by hash lock with timeouts: `HashLock.sol`, a UI-free `@evmb/htlc`, "Advance N blocks", a two-column Cross-chain swap page with reports, and three walkthroughs (claim, refund, unsafe) that the wizard ribbon drives end to end across both chains.

**Architecture:** One `HashLock` per chain; the maker's lock carries the terms (wanted chain id, contract, token, amount) and is the offer. `@evmb/htlc` reads both chains and derives the swap's phase and report from state and events only. The page plays both parties via the acting account; the maker's secret lives in the kv table `secrets` (and workspace files) until claimed.

**Tech Stack:** Bun 1.3.13 workspace, TypeScript, viem, webevm 0.9.1, solc 0.8.38 + OpenZeppelin 5.6.1, React 19 + Tailwind 4.

**Spec:** `evm-benchmarks/docs/superpowers/specs/2026-11-22-cross-chain-swap-design.md` — "Decided with Aaron" and "Settled after the builder check" are binding. Board t-62. New ADR-0021.

## Global Constraints

- **Contract ABI (exact):** `struct Lock { address sender; address recipient; address token; uint256 amount; bytes32 hash; uint64 timeoutBlock; Status status; uint64 closedBlock; bytes32 secret; string wantChain; address wantLock; address wantToken; uint256 wantAmount; }`, `enum Status { None, Locked, Claimed, Refunded }`; `nextId` from 1; `locks(id)`; `lock(token, amount, recipient, hash, timeoutBlock, wantChain, wantLock, wantToken, wantAmount) returns (uint256 id)`; `claim(id, secret)` (recipient only, `keccak256(abi.encodePacked(secret)) == hash`, `block.number < timeoutBlock`); `refund(id)` (sender only, `block.number >= timeoutBlock`); events `Locked(uint256 indexed id, address indexed sender, address indexed recipient, bytes32 hash, address token, uint256 amount, uint64 timeoutBlock)`, `Claimed(uint256 indexed id, bytes32 secret)`, `Refunded(uint256 indexed id)`; errors `NotLocked(uint256 id, uint8 status)`, `NotRecipient()`, `NotSender()`, `BadSecret()`, `Expired(uint64 timeoutBlock)`, `NotExpired(uint64 timeoutBlock)`, `BadLock()`. `BadLock` refuses zero amount, zero recipient, `timeoutBlock <= block.number`, and terms (non-empty `wantChain`) with a zero `wantToken` or `wantLock`. A lock with empty `wantChain` is an answer. SafeERC20, `nonReentrant`, CEI.
- **Pairing:** an answer on B pairs with the opening lock on A only when hash equal, answer.sender = opening.recipient, answer.recipient = opening.sender, answer.token = opening.wantToken, answer.amount ≥ opening.wantAmount, and the answer is on `wantLock` of chain `wantChain`; anything else with the same hash is ignored.
- **Time:** defaults maker timeout = head A + 100, taker timeout = head B + 50; safety margin 10 blocks: safe iff `(T_A − headA) ≥ (T_B − headB) + 10`. Unsafe → warning + explicit confirm "Lock anyway"; reports flag "unsafe timeouts".
- **`?as=` is an account** (existing links); role comes from the locks. Second chain param `chainB`.
- **Secret:** 32 random bytes (`crypto.getRandomValues`), `hash = keccak256(secret)`; kv table `secrets` keyed by hash → `{ secret, chain, lockId }`; included in workspace files (`secrets` table, validated as 32-byte hex keyed by its own hash); shown only to the maker (masked, "Reveal").
- **Reports:** per transaction `/xswap/report?tx=&chain=` (decoded error + fix copy); per swap `/xswap/report?hash=&chain=&chainB=` from `swapReport` (locks, steps with chain/tx/block, balance changes per chain, secret once revealed, outcome `completed | refunded (maker|taker|both) | stuck`, "unsafe timeouts" flag); Download JSON.
- **Copy:** sidebar "Cross-chain swap" (Markets, after Swap), route `/xswap`; app bar "Cross-chain swap · {B} ({chainA}) ⇄ {Q} ({chainB})"; "Deploy HashLock.sol?"; "Advance {n} blocks"; "Lock {amt} {B} on {chainA}"; "Lock {amt} {Q} on {chainB} to accept"; "Claim {amt} {Q} on {chainB} (reveals the secret)"; "Claim {amt} {B} on {chainA}"; "Refund"; "Lock anyway"; unknown chain "chain not in this browser"; benchmark chains "Benchmark chains keep no contract records".
- **Package boundaries:** `@evmb/htlc` imports nothing from `packages/web`; no React/DOM; deps `viem`, `@evmb/assets`; dev deps `webevm`, `@evmb/contracts`; layout like `packages/swap`.
- **Web:** tokens only, contrast tests, three themes, phone width; real data only; data captured at origin; `locksFor` reads `Locked` logs from the contract's deploy block → risk + backlog card referencing ADR-0021.
- **Every task end:** `bun test` from `evm-benchmarks` (R11 exit crash may follow passing tests — rerun until a summary line, max 3), `make build`, tsc on changed files (`bunx --package typescript@5 tsc --noEmit --strict --jsx react-jsx --moduleResolution bundler --module esnext --target es2022 --skipLibCheck --resolveJsonModule <files>`, ignore TS5097 and the known Studio/templates errors). Every test disposes every node.
- **Docs only in `evm-benchmarks/docs/`.** Regenerate cards with `node_modules/.bin/{agile,adr,risk-register} card <file> <dir>`.
- **Git:** branch `xswap` from `master`; `git commit --only -m … -- <paths>` (new files `git add -N`); never commit `design/`; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; git writes need `dangerouslyDisableSandbox: true`; a `bun.lock` change committed alone.

## Review Focus

1. **The wizard drives the whole swap.** Each of the three walkthroughs runs headless AND, in the ribbon, every step lands on the real page (right chain A/B, acting account, pair, prefilled amounts/timeouts) and the step's action is the page's own button; ribbon navigation keeps `chain`, `chainB`, `as`. Pinned by Task 5.
2. **Secret leaks.** Nothing but the maker's view and the maker's claim tx ever shows or sends the secret (not the taker's view, not reports before the claim, not URLs). Pinned by Tasks 3-4.
3. **Stray locks.** A third account locking on B with the same hash, or an answer with the wrong token/amount/recipient, never pairs and never unlocks a Claim button. Pinned by Task 2.
4. **Timeout edges.** Claim at `timeoutBlock − 1` succeeds; at `timeoutBlock` reverts `Expired`; refund at `timeoutBlock − 1` reverts `NotExpired`; the page's countdown and buttons agree with those blocks. Pinned by Tasks 1-2 and 4.
5. **Reloads and files.** Mid-swap reload, and Save → New → Open, keep the swap (locks on chain, secret in kv/file): the maker can still claim. Pinned by Task 3.
