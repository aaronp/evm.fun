> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GBP/USD liquidity pool — `Pool.sol` (one per pair, its own LP token), a UI-free `@evmb/pool` that quotes exactly what the contract does, a Pool page following Aaron's screenshot, a pool reference price on the Trade page, an `amm-swap` benchmark and a `gbp-usd-pool` walkthrough.

**Architecture:** `Pool.sol` keeps reserves in storage and does x·y = k with a 0.30% input fee; LP shares are 18-decimal whole-unit shares. `@evmb/pool` mirrors the integer maths to the unit and reads pools found from contract records plus their on-chain `base()`/`quote()` (unordered pair). The web app composes it like Swap.

**Tech Stack:** Bun 1.3.13 workspace, TypeScript, viem, webevm 0.9.1 (tests), solc 0.8.38 + OpenZeppelin 5.6.1 (ERC20, SafeERC20, ReentrancyGuard, Math.sqrt, IERC20Metadata), React 19 + Tailwind 4.

**Spec:** `evm-benchmarks/docs/superpowers/specs/2026-11-21-pool-design.md` — its "Settled after the builder check" section is binding. ADR-0019. Layout reference (git-ignored, never commit): `evm-benchmarks/design/step4/Pool.png`.

## Global Constraints

- **Package boundaries:** `@evmb/pool` imports nothing from `packages/web`; no React/DOM; runtime deps `viem`, `@evmb/assets`; dev deps `webevm`, `@evmb/contracts`; NO dependency (dev or runtime) on `@evmb/core` or any approach package. Layout like `packages/swap`.
- **Maths (contract and package identical, integer, floors):** fee 30 bps on input: `inWithFee = amountIn·9970`; `out = inWithFee·Rout / (Rin·10000 + inWithFee)`. First deposit: `shares = floor(√(baseIn·10^(18−db) · quoteIn·10^(18−dq))) − 1000`, 1000 minted to `0x000000000000000000000000000000000000dEaD`. Later deposits: `shares = min(baseIn·S/Rb, quoteIn·S/Rq)` (floor), and only the proportional amounts are pulled: `baseUsed = ceil(shares·Rb/S)`, `quoteUsed = ceil(shares·Rq/S)` (never more than the amounts offered; the pool never loses to rounding; the package mirrors it). Remove: `base = shares·Rb/S`, `quote = shares·Rq/S` (floor). Decimals > 18 → `BadToken`.
- **Price units:** quote raw units per one whole base unit (same as `@evmb/orderbook`), shown 4 dp; price impact = move of the pool price excluding the fee, in bps.
- **Unordered pair:** a pool for {A, B} is found and shown in either orientation; deploying refuses if one exists in either order.

## Review Focus

1. **Quote = execution across decimals.** GBP 2 dp / USD 6 dp and an 18-dp pair: `quoteSwap`, `quoteAdd`, `quoteRemove` equal the contract's results to the raw unit, both directions. Pinned by Task 2 tests on a real chain.
2. **Unbalanced add.** Adding at a ratio off the pool's: only the proportional amounts are pulled, the pool never loses to rounding, the depositor's surplus stays in their wallet. Pinned by Tasks 1 and 2.
3. **Slippage revert.** Someone trades first; the second swap reverts `Slippage(out, min)` and moves nothing; the page shows it. Pinned by Task 1 and Task 4.
4. **Reverse orientation.** A pool deployed as (USD, GBP) shows on the GBP/USD page with the right price, reserves x/y and curve; Studio refuses a duplicate. Pinned by Task 3 tests.
5. **Empty pool.** Swap/remove on an empty pool → `NoLiquidity`; the page offers only Add liquidity with free amounts and shows the initial price. Pinned by Tasks 1 and 4.
