# Links and fix-it actions: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `?chain=&as=` on every page, synced both ways with the app's selection; "Request {amount} {SYM} from {issuer}" on balance shortfalls, opening the Send dialog as the issuer with `back=`, returning automatically with a notice; the walkthrough ribbon shows the same fix.

**Architecture:** Pure URL helpers in `src/links.ts`; one `UrlSync` component in the app shell; a one-shot notice in sessionStorage; a shared `<Shortfall>` component used by the forms; page handlers may return `{ message, fix }`.

**Tech Stack:** React 19, react-router 7 (HashRouter), Tailwind 4, Bun tests (SSR via react-dom/server).

**Spec:** `evm-benchmarks/docs/superpowers/specs/2026-11-21-links-and-fixes-design.md`.

## Global Constraints

- Param names exactly: `chain`, `as`, `send`, `amount`, `back`, `asset` (existing). `back` is URI-encoded.
- `as` written as the account label when unique among accounts, else the checksummed address; read either (label match case-sensitive, address case-insensitive).
- State → URL uses `replace` (no history entries); URL → state only when the params differ from the selection.
- Copy: button "Request {amount} {SYM} from {issuer}"; notice "Received {amount} {SYM} from {issuer}"; unknown chain notice "No chain {id} in this browser"; unknown persona "No account {as} in this browser".
- Tokens only, three themes, phone width; real data only; outside a walkthrough pages behave as before apart from the added params and buttons.
- Every task end: `bun test` from `evm-benchmarks` (R11 exit crash may follow passing tests — rerun until a summary line, max 3), `make build`, tsc on changed files (`bunx --package typescript@5 tsc --noEmit --strict --jsx react-jsx --moduleResolution bundler --module esnext --target es2022 --skipLibCheck --resolveJsonModule <files>`, ignore TS5097 and the known Studio/templates errors).
- Git: `git commit --only -m … -- <paths>` (new files `git add -N`); commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; git writes need `dangerouslyDisableSandbox: true`; never commit `design/`.

## Review Focus

1. **Loops.** URL → state → URL must settle in one round (no navigation loop, no fight with the ribbon's own navigation or the chain switcher).
2. **Round trip.** A shortfall on Swap as bob → Request → Send as alice → back to the same Swap URL as bob with the pair and the notice.
3. **Ambiguous labels.** Two accounts labelled the same → URL uses the address; a label URL picks the first match.
4. **Walkthrough interplay.** Ribbon navigations (which add `?auto=`) keep `chain`/`as`; a fix from the ribbon returns to the failing step's page.
5. **Bad links.** Unknown chain/as, a `back` pointing off-site (only same-app hash paths allowed), `amount` not parseable → safe.
