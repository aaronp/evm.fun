# Same-chain swap (step 2): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Swap.sol` (escrowed offers, atomic take, cancel), a UI-free `@evmb/swap` package, a Swap page and an execution-report page following `design/step2/`, a Studio "Deploy Swap.sol" action, and an `offer-fill` benchmark scenario.

**Architecture:** One `Swap` per chain, found from contract records. `@evmb/swap` reads the book straight from contract storage (`offers(1..nextId-1)`, ADR-0016), derives the bid/ask view with exact BigInt maths, and builds execution reports and Activity from receipts and logs. The web app composes it with the existing `signAndSend`, `parseAmount`/`formatAmount` and the assets registry. No new stored state.

**Tech Stack:** Bun 1.3.13 workspace, TypeScript, viem, webevm 0.9.1 (tests), solc 0.8.38 + OpenZeppelin 5.6.1, React 19 + Tailwind 4.

**Spec:** `evm-benchmarks/docs/superpowers/specs/2026-11-20-swap-design.md` — its "Settled after the builder check" section is binding. ADR-0016 in `evm-benchmarks/docs/adr/decisions.md`. Mockups (git-ignored, never commit): `evm-benchmarks/design/step2/Swap-offers--same-chain/Swap.dc.html` and `evm-benchmarks/design/step2/Swap-execution-report-html/SwapReport.dc.html`; their look and copy win over this plan. `design/step2/orderbook` is step 5 — out of scope.

## Global Constraints

- **`@evmb/swap` boundaries:** imports nothing from `packages/web`, no DOM/React/IndexedDB. Runtime deps `viem` and `@evmb/assets` (types, `Request`) only; `webevm` and `@evmb/contracts` are devDependencies. Same file layout as `packages/assets` (`src/`, `test/`, `README.md`).
- **Contract:** exactly the spec's interface: `Status { None, Open, Filled, Cancelled }`, `nextId` starts at 1, `offers(id)` public, events `OfferMade(uint256 indexed id, address indexed maker, address giveToken, uint256 giveAmt, address getToken, uint256 getAmt)`, `OfferTaken(uint256 indexed id, address indexed taker)`, `OfferCancelled(uint256 indexed id)`, errors `OfferNotOpen(uint256 id, Status status)`, `NotMaker(uint256 id)`, `BadOffer()`. SafeERC20, ReentrancyGuard, checks-effects-interactions.
- **Never cached:** offers, balances, allowances, Activity and reports are read from the chain each time. No new kv namespaces.
- **Swap identity:** contract record named `Swap` whose ABI passes `isSwapAbi`; newest (`deployedAt`/list order) wins. Report page uses the tx's `to`.
- **Price:** quote per base; quote amount = amount × price rounded half-up to quote decimals; book compares exactly (BigInt cross-multiplication with decimals), displays 4 dp, ties lowest id first.
- **ERC-20 only** in offers; pair pickers list the chain's ERC-20 assets (not native).
- **Benchmark (ephemeral) chains:** Deploy Swap and the Swap page are disabled with "Benchmark chains keep no contract records" (match the assets wording style).
- **Copy, verbatim from the mockups:** "each fills whole", "Click an offer to take it.", "One transaction: your {payAsset} goes to {maker} and the escrowed {giveAsset} comes to you — or neither happens.", "You escrow now", "You get when taken", "Create offer & escrow", "Acting as", "What happened", "Balance changes", "On-chain record", "Download JSON", the crossing note "Someone is already buying at {X} or better — take their offer instead. Swap doesn’t match offers for you." (and its selling twin from the mockup), the allowance fix "Approve Swap to spend at least {amt} {SYM} from {taker}, then take the offer again. ## Review Focus

1. **Same-block race.** Two takes of one offer in the same block: the loser's report says `OfferNotOpen(Filled)` and names the winning taker and block — not a replay of a still-open offer. Pinned by a Task 3 test on a manual-mining chain (approach 02) plus a pure ordering test.
2. **Mixed decimals.** Base with 2 decimals, quote with 6 (and 18): the form's quote amount, the stored `getAmt`, the book price and best bid/ask are exact and consistent. Pinned by Task 2 book tests and a Task 6 pure-form test.
3. **Short allowance or balance on take.** The take is still sendable; the tx lands reverted and its report shows the decoded `ERC20InsufficientAllowance`/`ERC20InsufficientBalance` with the right fix copy, and no tokens moved. Pinned by Task 3 tests.
4. **Cancel and re-take.** Non-maker cancel → `NotMaker`; take after cancel → `OfferNotOpen(Cancelled)`; cancel returns exactly the escrow; double take reverts. Pinned by Task 1 tests.
5. **Chain switch / fork.** The Swap page finds the Swap of the *current* chain only, a forked chain shows the parent's offers (state copied) and its own Swap record, and a chain without one shows "Deploy Swap.sol?". Pinned by a Task 2 `findSwap` test and a Task 5 web chain test using `createFrom`.

### Task 2: `@evmb/swap` — identity, calls, offer reads, book

**Files:**
- Create: `packages/swap/package.json` (`@evmb/swap`, `main: src/index.ts`, deps `viem`, `@evmb/assets: workspace:*`; devDeps `webevm` 0.9.1, `@evmb/contracts: workspace:*`, `@evmb/approach-02-seq-memory: workspace:*` for the same-block test in Task 3), `packages/swap/src/{index.ts,types.ts,abi.ts,calls.ts,read.ts,book.ts,errors.ts}`
- Test: `packages/swap/test/{abi,read,book,errors}.test.ts`
- Run `bun install` (lockfile: see Global Constraints).

**Interfaces:**
- Consumes: `Request` from `@evmb/assets`; `Swap` ABI from `@evmb/contracts` (tests) — the package embeds its own ABI const (`swapAbi`) so it has no runtime dep on contracts.
- Produces:
  - `type OfferStatus = 'none'|'open'|'filled'|'cancelled'`
  - `type Offer = { id: bigint; maker: Address; giveToken: Address; giveAmt: bigint; getToken: Address; getAmt: bigint; status: OfferStatus }`
  - `swapAbi`, `isSwapAbi(abi): boolean`, `findSwap(records: {name: string; address: Address; abi: Abi}[]): Address | undefined` (last matching record wins)
  - `makeOfferCall(swap, giveToken, giveAmt, getToken, getAmt)`, `takeCall(swap, id)`, `cancelCall(swap, id)` → `{to, data}`
  - `readOffers(request, swap): Promise<Offer[]>` (ids 1..nextId-1, all statuses)
  - `type Side = 'ask'|'bid'`; `type BookRow = Offer & { side: Side; base: bigint; quote: bigint; price: { num: bigint; den: bigint } }`
  - `book(offers, base: {address, decimals}, quote: {address, decimals})` → `{ asks: BookRow[]; bids: BookRow[]; bestBid?: BookRow; bestAsk?: BookRow; spread?: {num, den}; escrowed: { base: bigint; quote: bigint } }` — asks = open offers giving base for quote, ascending price; bids = open offers giving quote for base, descending; ties lowest id first; other pairs ignored; `escrowed` sums open offers' give side per token.
  - `priceText(price, dp = 4): string`
  - `quoteFor(amount: bigint, price: string, baseDecimals, quoteDecimals): bigint` (half-up; throws "Invalid price" for ≤0 / non-numeric / more than 18 fractional digits)
  - `decodeSwapError(data: Hex): { name: string; args: Record<string, unknown> } | undefined` — `OfferNotOpen`, `NotMaker`, `BadOffer`, `ERC20InsufficientAllowance`, `ERC20InsufficientBalance`; `undefined` if unknown.

- [ ] Failing tests: `isSwapAbi` true for `Swap.abi`, false for `erc20Abi`/`AtomicSwap.abi`; `findSwap` picks the last `Swap` record and ignores a record named `Swap` with a non-Swap ABI; calls decode back with viem; `readOffers` against webevm returns made/taken/cancelled offers with correct statuses; book: GBP(2dp)/USD(6dp) asks ascending, bids descending, tie → lower id first, an offer in another pair ignored, best bid/ask and spread exact, escrowed sums open offers only; `quoteFor('1.27' × 1,000.00 GBP)` = 1,270.000000 USD and half-up rounding at the quote's last digit; `priceText` 4 dp; `decodeSwapError` on real revert data from each error.
- [ ] RED, implement, GREEN. Commit (not `bun.lock`).

### Task 3: Execution report and Activity

**Files:**
- Create: `packages/swap/src/report.ts`, `packages/swap/src/activity.ts`
- Test: `packages/swap/test/report.test.ts`, `packages/swap/test/activity.test.ts`

**Interfaces:**
- Produces:
  - `type ReportStep = { title: string; body: string; evidence: string; ok: boolean; detail?: string }`
  - `type TakeReport = { outcome: 'taken'|'reverted'; tx: Hash; block: bigint; txIndex: number; gasUsed: bigint; swap: Address; offer: Offer; taker: Address; error?: {name: string; args: Record<string, unknown>; raw?: Hex}; reason?: 'allowance'|'balance'|'filled'|'cancelled'|'other'; winner?: { taker?: Address; block: bigint; tx: Hash; sameBlock: boolean }; steps: ReportStep[]; balanceChanges: { holder: Address; token: Address; delta: bigint }[]; logs: string[]; reconstructedNow?: boolean }`
  - `takeReport(request, txHash): Promise<TakeReport>` (throws "Not a Swap take" when the tx isn't `take(id)`; the Swap is the tx's `to`; offer read from storage; for a revert: a status-changing `OfferTaken`/`OfferCancelled` for that id ordered before the tx (block, txIndex) → reason filled/cancelled + `winner`; otherwise `eth_call` at block−1 with the tx's from/to/data → decode → allowance/balance/other; if the historical call is unsupported, call at `latest` and set `reconstructedNow`).
  - `precedes(a: {block, txIndex}, b: {block, txIndex}): boolean` (exported, pure).
  - `type ActivityItem = { kind: 'offered'|'taken'|'cancelled'|'reverted'|'approved'; id?: bigint; actor: Address; tx: Hash; block: bigint; txIndex: number; token?: Address; amount?: bigint; reason?: TakeReport['reason'] }`
  - `activity(request, swap, pairTokens: Address[]): Promise<ActivityItem[]>` newest first: made/taken/cancelled from Swap logs; `approved` from `Approval` logs of `pairTokens` with spender = swap (topic filter); `reverted` takes from a block scan for txs to `swap` with receipt status 0 and selector `take`.
  - Steps follow the report mockup: success = Offer #n made (OfferMade), take(n) sent by {taker} (block), Pay leg (transferFrom), Deliver leg (transfer), Offer closed (OfferTaken); failure = the failing step with the decoded error as `detail` and the mockup's titles/bodies. `balanceChanges` from `Transfer` logs (empty for reverts).
- [ ] Failing tests (webevm): successful take → outcome taken, 5 ok steps, balance changes taker +give/−get, maker +get, Swap −give, gasUsed > 0; short allowance → reverted, reason allowance, `ERC20InsufficientAllowance` args, no balance changes; take after cancel → reason cancelled with winner tx; take after another take in an earlier block → reason filled, winner taker and `sameBlock: false`; **same block** on approach 02 with manual mining: two takes submitted then one mine → the second's report has reason filled, `sameBlock: true`, winner = first taker; `precedes` truth table; non-take tx → "Not a Swap take"; `activity` lists offered/approved/taken/cancelled/reverted in newest-first order and ignores approvals of other tokens or spenders.
- [ ] RED, implement, GREEN. Commit.
