# evm-benchmarks Plan 4: Playground look & feel and themes

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle `packages/web` to the designer's mockups (`evm-benchmarks/design/project/*.dc.html`) using semantic colour tokens, with three switchable themes: Dark, Light and Paper. Every existing feature stays.

**Architecture:**
- `src/theme/tokens.css` is the single source of colour. It defines `--c-*` variables per `:root[data-theme=dark|light|paper]`.
- Tailwind 4's `@theme inline` maps those variables to utilities (`bg-surface`, `text-muted`, …).
- A pre-paint inline script in `index.html` sets `data-theme`.
- Shared UI primitives and an icon module are rebuilt to match the mockups, then each page is restyled.
- Two pure tests keep it honest:
  - **Contrast:** parses `tokens.css` and computes WCAG ratios.
  - **No-raw-colour guard:** greps `src/` for hex/rgb/hsl and Tailwind palette classes. It holds a shrinking allowlist of not-yet-ported files.

**Tech Stack:** React 19, Tailwind 4, Vite, CodeMirror 6, Bun test. No new runtime dependencies.

**Spec:** `evm-benchmarks/docs/superpowers/specs/2026-11-19-playground-theme-design.md`. Read the "Settled after the builder check" section too; it binds.

## Global Constraints

- **Tokens:** the spec's token table, with Dark values verbatim unless a contrast pair in the spec fails. Each nudge gets a comment giving the original value.
  - Light and Paper values are the builder's choice.
  - Paper is anchored on bg `#EFE8DC`, surface `#FFFDF7`, text `#2B2622` and muted `#5F574E`.
- **Contrast pairs and thresholds:** exactly as listed in the spec's "Contrast test" bullet.
  - Text pairs must be at least 4.5:1, and the focus ring at least 3:1.
  - `disabled` and decorative borders are exempt.
- **No raw colours** in `src/**/*.{ts,tsx,css}` outside `src/theme/tokens.css`:
  - no hex, `rgb(`/`rgba(`/`hsl(`
  - no Tailwind palette utilities (`(bg|text|border|ring|outline|divide|fill|stroke|from|to|via|placeholder|accent|caret|shadow)-(slate|gray|zinc|neutral|stone|red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose)-\d{2,3}`, plus `-white`/`-black`)
  - `var(--…)` and `color-mix(…var(--…)…)` are allowed.
- **Theme persistence:**
  - Stored in localStorage key `evmb.theme`, with values `dark`, `light` or `paper`.
  - If storage fails, it silently falls back to the OS default.
  - First visit follows `prefers-color-scheme`: Dark if dark, Light otherwise.
  - `data-theme` is set before first paint.
- **Fonts:** Inter (UI), Space Grotesk (headings and brand), JetBrains Mono (code, addresses, hashes). Loaded via a Google Fonts `<link>`, with system fallbacks.
- **Behaviour unchanged.** All existing tests stay green. The address datalist, ChainTypeHelp, StorageNotice, `KEYS_WARNING` text, phone-width layout, `role="alert"` validation and every route keep working.
- **No placeholder or invented data.** The mockups' bracketed values, assumed scenario descriptions and sender labels never appear. Out-of-scope mockup panels are dropped, not stubbed.
- **Out of scope** (the spec's non-goals): Workspace dashboard, Getting-started tracker, chain wizard, Studio file sidebar and tabs, Simulate, session history, state diff, Replay, export JSON, percentile chart, p90/p99.9, run comparison.
- **Project docs and git:**
  - Board `docs/board/board.md` (strict format). Real `date -u` timestamps, `owner: Claude`, and the card checks print `Wrote`.
  - Branch `plan3-playground`. Git writes and `bun install` need the sandbox disabled.
  - Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Interfaces:**
- `tokens.css`: `:root[data-theme="dark"|"light"|"paper"] { --c-bg:…; --c-panel:…; … }` for every token in the spec table, with `-` in names. For example `--c-text-2`, `--c-accent-soft`, `--c-on-accent`, `--c-code-keyword`.
- `index.css`:
  - `@theme inline { --color-bg: var(--c-bg); … }` for each token, so `bg-bg`, `bg-surface`, `text-text`, `text-muted`, `border-line`, `text-accent`, `bg-warn-soft` and so on work.
  - `--font-sans` (Inter), `--font-display` (Space Grotesk), `--font-mono` (JetBrains Mono).
  - `body` gets `bg-bg text-text font-sans`, plus `color-scheme` per theme.
- `theme.ts`:
  - `type Theme = 'dark'|'light'|'paper'`
  - `THEMES: Theme[]`
  - `initialTheme(stored: string|null, prefersDark: boolean): Theme`
  - `getTheme(): Theme`
  - `setTheme(t: Theme): void`, which sets `document.documentElement.dataset.theme` and writes `evmb.theme` inside a try/catch
  - `onThemeChange(cb): () => void`
- `index.html` has an inline `<script>` in `<head>`, before CSS, that runs the same logic as `initialTheme` (duplicated deliberately, about 3 lines, with a comment pointing at `theme.ts`).
- `contrast.test.ts`:
  - Reads `tokens.css` and parses each theme block into a map.
  - Implements the WCAG relative-luminance ratio.
  - Asserts every spec pair in every theme. A failing assertion names the theme, the pair and the ratio.
- `no-raw-colours.test.ts`:
  - Globs `src/**/*.{ts,tsx,css}`, excluding `src/theme/tokens.css`.
  - Asserts no matches for the Global Constraints patterns, except for files in `const NOT_YET_PORTED = [...]`. That list is initially every file that currently matches.
  - A second assertion checks that each allowlisted file still matches, so the list can't go stale.
